# 식사 중복 방지와 자동 빈 시간 슬롯 설계

## 목표

여행 전체의 대표 식사 장르가 반복되지 않게 하고, 안목 돼지국밥은 가까운 부산역점의 19일 점심 한 번으로만 배치한다. 각 날짜에는 새 사용자 요청 한 건을 받을 수 있는 실제 빈 시간을 계산해 표시하고, 총괄 에이전트가 기존 일정의 권역·고정 시간·이동 버퍼를 지키며 자동으로 순서화한다.

## 식사 규칙

- 점심·저녁의 `대표 선택`은 여행 전체에서 같은 장르를 반복하지 않는다.
- 안목은 19일 부산역점의 돼지국밥 대표 선택 하나로만 둔다. 다른 지점과 다른 끼니에는 대표·후보 모두에 넣지 않는다.
- 각 식사 슬롯은 권역에 맞는 세 곳 이상의 대안을 유지한다. 대안은 예약 실패와 대기 상황에 대비한 것이며, 대표 선택을 바꾸면 총괄 에이전트가 전역 장르 중복을 다시 검사한다.
- 8개 대표 식사는 밀면, 해산물, 시장 간식, 한우 갈비, 테마파크·캐주얼 식사, 이자카야, 기장 한식, 돼지국밥처럼 서로 다른 장르로 구성한다.
- 사용자가 제공한 해운대 식당은 17일 해운대권 후보로 남기고, 실제 대표 선택은 한 끼에 하나만 채택한다.

## 시간 슬롯 규칙

- 날짜별 오전·낮·오후 블록은 기존 고정 일정과 권역을 유지한다.
- 총괄 에이전트는 각 날짜의 블록 사이에서 실제 비어 있는 시간 구간을 계산해 `openSlot` 하나를 만든다.
- 입력 가능한 새 요청은 날짜별 한 건으로 제한한다.
- 새 요청은 같은 권역의 가장 이른 적합한 빈 시간에 배치한다. 이동 시간이 필요한 요청이면 다음 빈 구간을 사용하고, KTX·체크인·체크아웃·물놀이 같은 고정 블록은 움직이지 않는다.
- 적합한 빈 시간이 없으면 일정을 임의로 밀어 넣지 않고 `warnings`에 충돌 이유와 가능한 대체 시간만 기록한다.

## 데이터와 에이전트 계약

`mealSlots`의 후보에는 `genre`와 함께 `primary` 불리언을 둔다. 식당 에이전트는 각 슬롯의 대표와 대안을 반환하고, 총괄 검수는 대표 장르·식당 이름·안목 지점의 전역 중복을 검사한다.

`defaultBlocks`에는 각 블록의 시작·종료 범위를 추가한다. 일정 에이전트는 날짜별 `openSlot`을 반환하고, 사용자 요청은 `customRequests[date]`로 저장한다. 동선 에이전트는 자동 배치된 요청을 지도 경로의 적절한 위치에 끼워 넣는다.

## 검수와 화면

- 총괄 에이전트는 반복 장르, 안목 중복, 하루 두 건 이상의 사용자 요청, 고정 교통·숙소 충돌, 빈 시간 부족을 경고한다.
- 일정 탭은 오전·낮·오후 블록과 자동 배치된 요청을 시간순으로 보여 주며, 아직 사용되지 않은 `요청 대기` 빈 시간을 표시한다.
- 맛집 탭은 대표 선택과 대안을 구분하고, 대표 선택의 장르가 전 여행에서 중복되지 않음을 보여 준다.
- 개요의 전체 일정 재계산은 저장된 요청을 다시 배치하고 모든 탭의 일정·동선·식사 결과를 동시에 갱신한다.

## 검증

- 대표 장르와 안목 식당이 전체 여행에서 한 번만 선택되는 단위 테스트를 추가한다.
- 하루당 두 건의 사용자 요청은 경고되며 두 번째 요청은 배치되지 않는지 확인한다.
- 16~19일의 요청이 빈 시간에만 배치되고 19일 KTX·부산역 버퍼가 유지되는지 확인한다.
- 알뜰·균형·여유 모두에서 대표 장르 규칙과 세 곳 이상의 대안이 유지되는지 확인한다.
- 전체 일정 재계산 후 일정·탐색·맛집 화면 계약과 지도 경로 순서를 확인한다.
