# 부산 Tokidoki 여행 총괄 에이전트 설계

## 방향

SummerVacationInBusan은 Tokidoki의 정보 밀도와 탭 구조를 유지하되, 콘텐츠를 부산 4일 여행으로 교체한다. 정적 GitHub Pages에서 동작해야 하므로 외부 LLM 호출 대신 입력 데이터와 규칙을 사용하는 결정적 오케스트레이터를 둔다. 사용자가 일자별 흐름을 바꾸면 전체 여행을 다시 계산하고, 각 전문 에이전트의 판단과 충돌을 공개한다.

## 비주얼 스킨

- 여름 부산 바닷가를 기준으로 `sea blue`, `deep navy`, `sand`, `coral`, `foam white`를 디자인 토큰으로 사용한다.
- 첫 화면은 일정과 바다 지도/권역을 즉시 보여주며, 마케팅형 히어로보다 실제 여행 도구를 우선한다.
- 물결, 조수선, 해안 지도선을 작은 장식으로 사용하되 과도한 그라데이션이나 장식용 원형 요소는 사용하지 않는다.
- 카드와 탭은 낮은 모서리 반경, 선명한 대비, 넉넉한 터치 영역으로 구성해 모바일에서도 일정 입력과 재계산이 편해야 한다.
- 지도·일정·경고·출처가 한 색상에 묻히지 않도록 파랑은 이동/바다, 산호는 실행/예약, 모래색은 식사/휴식에 제한한다.

## 에이전트 구성

| 에이전트 | 책임 | 주요 입력 | 주요 출력 |
| --- | --- | --- | --- |
| 총괄 | 실행 순서, 충돌 해결, 최종 결정 | 전체 여행 컨텍스트 | 최종 일정, 결정, 경고 |
| 일정 | 날짜별 목적과 체류 시간 배치 | 일자별 흐름, 고정 시간 | 시간 블록 |
| 동선 | 권역 묶음과 이동 순서 | 장소, 숙소, 시간 블록 | 권역·순서·이동 메모 |
| 숙소 | 체크인/체크아웃, 짐 이동 | 두 호텔, 날짜 | 숙소 거점과 짐 규칙 |
| 교통 | KTX, 호텔 이동, 귀환 버퍼 | 교통 고정값, 동선 | 출발 마감·버퍼·경고 |
| 식당/맛집 | 권역과 영상 출처 기반 식사 | 시간 블록, 장소, 영상 | 식사 후보와 예약 메모 |
| 놀거리 | 아이 선호, 날씨, 체력 | 일자 흐름, 계절, 권역 | 체험·휴식·우천 대안 |

## 재계산 규칙

1. 사용자가 `dayFlows` 중 하나를 수정한다.
2. 총괄 에이전트가 canonical context와 수정된 흐름을 병합한다.
3. 일정 에이전트가 고정 교통 시간을 먼저 잠근다.
4. 동선 에이전트가 숙소 기준으로 권역을 묶는다.
5. 숙소/교통 에이전트가 이동과 체크인, KTX 버퍼를 검증한다.
6. 식사/놀거리 에이전트가 남은 시간과 권역에 후보를 배치한다.
7. 총괄이 `decisions`와 `warnings`를 만들고 화면을 갱신한다.

## 핵심 정책

- 16일은 부산역·초량·남포·영도권을 우선한다.
- 17일은 해운대 관광과 파라다이스호텔 물놀이를 한 날에 묶는다.
- 18일은 해운대 반복을 피하고 오시리아 체험을 기본값으로 둔다. 롯데월드 부산, 스카이라인 루지, 국립부산과학관, 센텀 실내 휴식을 상황별 후보로 둔다.
- 19일은 오전 씨메르 이후 체크아웃/짐 보관과 부산역 도착 버퍼를 최우선으로 한다.
- 현재 운영시간, 휴무일, 예약 가능 여부는 공식 링크를 “재확인 필요”로 표시한다.

## 구현 경계

- 전문 에이전트는 순수 함수로 작성하고 브라우저 DOM을 직접 조작하지 않는다.
- 화면 렌더링과 localStorage는 `app.js`가 담당한다.
- JSON은 여행 사실과 후보 장소의 원본이며, 에이전트는 이를 조합한다.
- 변경 요청은 서버 저장 없이 브라우저 localStorage에 저장한다.
